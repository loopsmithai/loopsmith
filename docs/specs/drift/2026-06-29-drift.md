### D-04: smith-agent exit-code semantics (invariant)
- **Type:** NEW
- **Domain / Topic:** api/agent-envelope
- **Current code:** Exit `0` = success (`result` present); `1` = failure (`error` present); `2` =
  discovery, no operation executed — `next` lists children, no `result`. Invariant: a discovery/group
  invocation exits `2`, never `0`, and carries no `result`. **Explicit clause:** an unparseable or
  incomplete command (clap parse error) is also treated as **discovery → exit 2** (with a help-style
  `next`), NOT as failure/exit 1. This is a deliberate design choice (the design doc defines exit 2 as
  "no operation executed"); spec it as a named invariant so it is consciously blessed, not inherited.
- **Current spec:** none
- **Proposed resolution:** ADD as SHALL (express as invariants, incl. the explicit parse-error clause)
- **Confidence:** high
- **Evidence:** `envelope.rs:38-41,111-120`; `agent_main.rs:19-32` (parse error → discovery/exit 2),
  `agent_main.rs:117,123,160`

### D-05: discovery-hints contract (next/related/recovery)
- **Type:** NEW
- **Domain / Topic:** api/agent-envelope  *(folded — see resolution; NOT a separate `command-graph` topic)*
- **Current code:** Each envelope's `next`/`related`/`recovery` entries are **runnable commands with
  the real `--org`/`--project`/`number` values baked in** (not `<placeholders>` except for values the
  agent must choose). Group/discovery envelopes' `next` lists the node's child operations; leaf
  successes carry workflow `next` + discovery `related`; failures carry failure-class `recovery`.
  (Internally these are produced by traversing a compile-time DOT command graph, but that mechanism
  is implementation detail and is **not** part of the contract.)
- **Current spec:** none
- **Proposed resolution:** ADD as SHALL, but **fold into `api/agent-envelope`** as hint-field
  invariants — the contract is a property of the envelope's `next`/`related`/`error.recovery` fields,
  so it must not live under a topic named after the excluded `command-graph`/DOT mechanism. Spec the
  **observable** contract only (runnable, real values; group `next` = children; failures carry
  recovery), never petgraph/DOT.
- **Confidence:** high (observable contract confirmed by reviewer); the internal graph size is not
  contract — earlier "33 nodes/124 edges" was inaccurate (actual ≈32 nodes/119 edges, and no test
  pins the real graph), so those numbers are dropped, not specced.
- **Evidence:** `agent_main.rs:78-120` (hint rendering with real values); observable contract verified.

### D-07: credential store & keyring naming  *(corrected by review — was built from design-doc intent)*
- **Type:** NEW
- **Domain / Topic:** auth/credential-store
- **Current code:** Credentials live in the OS Secret Service keyring via a generic
  `LocalKeyValueCredentialStore`. There are **two credential domains**, each with its own service name:
  - **App credentials** — `CredentialDomain::GitHubApp { agent_id }` → service `loopsmith.app.{agent_id}`.
  - **Installation token** — `CredentialDomain::GitHubInstallation { org }` → service
    `loopsmith.{org}.installation`, with a **two-tier legacy fallback probe**:
    `loopsmith.{org}.github-app` (pre-split format) → `botminter.{org}.github-app` (oldest format).
    The fallback is only consulted when the new service has no installation-id key.
  Key names (built by `credential_keys`): `{member}/github-app-id`, `{member}/github-app-client-id`,
  `{member}/github-app-private-key`, `{member}/github-installation-id`. Note: the installation-store
  **probe key is hardcoded to the literal `smith/github-installation-id`** (not parameterized by
  `agent_id`). `SMITH_KEYRING_DBUS` overrides the D-Bus session bus address when set.
- **Current spec:** none
- **Proposed resolution:** ADD as SHALL — capture the two service-name schemes and the two-tier legacy
  fallback as desired (the fallback is intentional backward-compat). Record the **hardcoded `smith/`
  probe prefix** (vs the parameterized `{member}/` key builder) as a **Known Issue** — it is an
  inconsistency, not a contract to bless.
- **Confidence:** high — read from compiled code (corrected from the earlier design-doc-based version).
- **Evidence:** `crates/smith/src/formation/local/linux/mod.rs:103-156` (domains, service names,
  two-tier fallback, hardcoded `smith/` probe); `git/manifest_flow.rs:85-99` (`credential_keys` key
  names); `formation/local/linux/credential.rs:210` (`SMITH_KEYRING_DBUS` override only)
