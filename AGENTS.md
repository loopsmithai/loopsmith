# AGENTS.md

Loopsmith is a kit for managing **loops** — a value-stream work model abstracted above any harness,
runtime, or task tracker. The code is a single Rust crate (`crates/smith/`) that builds **two
binaries**: `smith` (the human operator CLI) and `smith-agent` (the machine-readable CLI that coding
agents drive). The crate originated as a copy of the BotMinter `bm` crate and was stripped down by
deletion; only the modules that compile remain.

## Critical rules

- **Only compiled modules are real.** `crates/smith/src/lib.rs` gates which modules compile. The
  uncompiled BotMinter modules have been deleted; anything still commented out is a leftover
  reference, not a contract to wire against.
- **`smith-agent` output is a strict contract.** Every invocation emits one JSON envelope with
  defined exit codes — see [docs/specs/api/agent-envelope.md](docs/specs/api/agent-envelope.md). Do
  not add bare `println!` or change exit-code semantics without updating that spec.

## Quick start

```bash
cargo build                                   # builds both binaries
smith init                                     # register a GitHub App, store credentials
smith-agent github --org <org> auth-status     # verify auth (mints an installation token)
```

Local testing against Gitea: set `SMITH_GITHUB_API_BASE` / `SMITH_GITHUB_WEB_BASE` (see `demo.sh`).

## Conventions & patterns

- **Strip-by-deletion port.** The crate came from BotMinter and was reduced by deletion, never by
  rewriting. The strip is complete: 56,266 lines down to ~10,800. Restore nothing from history;
  author what is needed instead.
- **`SMITH_` env prefix** for all runtime overrides (`SMITH_GITHUB_API_BASE`, `SMITH_KEYRING_DBUS`).
- **Credentials live in the keyring**, not on disk — see
  [docs/specs/auth/credential-store.md](docs/specs/auth/credential-store.md).

### Naming conventions

- Plan dir naming: `e<id>-<slug>/`, `s<id>-<slug>/`, `e<id>-<slug>_s<id>-<slug>/`
- Task file naming: `task-NN-<slug>.md` (visible, descriptive, sortable)
- `docs/features/` = WHAT the system does (user perspective)
- `docs/specs/` = WHAT the system IS and HOW it works (system internals)
- `docs/plans/` = transient PDD planning artifacts (per-delivery, traceability)

### Formatting

- No circled-number emojis in docs. Use plain text headings and abbreviation labels
  (`CFG`, `REL`, `BHVR`) in traceability tables.
- Domain index files: always `index.md` with a `README.md` symlink for GitHub rendering.
- Index files are indexes, not specs. Actual spec content goes in its own `{topic}.md`.

### Adding a command to smith-agent

ALL steps required. Missing any one breaks the envelope, the graph, or the spec:

1. **DOT graph first** (`commands.dot`): add the node + `kind="child"` edge.
2. **Clap enum** (`agent_cli.rs`): add the variant.
3. **DOT node ID mapping** (`agent_main.rs`): add the match arm. Most likely step to miss.
4. **Implementation** (`agent_commands/github/<module>.rs`).
5. **Dispatch** (`agent_commands/github/mod.rs`): wire the match arm.
6. **Spec update** (`docs/specs/cli/smith-agent.md`).
7. **Build + test**: `cargo build`, run against real target, verify envelope.

DOT-first is non-negotiable. The graph is the spec. Code follows it.

### Testing infrastructure

All e2e and integration tests MUST run in containers. No host contamination.
Build on host, run in podman pod (Gitea + test runner share network namespace).
See `crates/smith/tests/e2e/run-in-container.sh`.

Uses rexpect (v0.7) for PTY-based wizard testing. Critical: use `spawn_bash()`,
not `spawn` (colored crate v3 IO Safety violation). Requires `NO_COLOR=1` and
`GH_CONFIG_DIR=/nonexistent`.

Gitea does NOT support the App manifest flow. Manifest flow testing requires a
mock server (future). See `references/interactive-cli-testing.md` in Smith's home
for the full testing guide.
